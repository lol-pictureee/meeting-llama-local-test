# Промт: локальный AI Meeting Summarizer (Go + Python + Docker)

Ты — опытный Go/Python-разработчик. Создай простой, реально запускаемый локальный сервис: пользователь загружает аудиозапись встречи и получает транскрипт и краткий протокол.

## Главные ограничения

- **Всё выполнение локальное. Никаких облачных AI-сервисов и внешних API. Никаких API-ключей.** Не добавляй OpenAI, Anthropic, Gemini Cloud, SaaS, аналитику, телеметрию или отправку файлов наружу.
- LLM: **`gemma4:12b` через локальный Ollama**. Используй только локальный адрес Ollama внутри Docker-сети; не используй модели с суффиксом `cloud`.
- Распознавание речи: **`faster-whisper` локально в Python**. Загрузка аудио и транскрипция не должны передаваться третьим сторонам.
- Стек: **Go + Python + Docker Compose**. Не добавляй Kubernetes, Redis, PostgreSQL, облачное хранилище, микросервисы без необходимости и сложную архитектуру.
- Храни файлы и данные на локальных Docker volumes. Секреты и API-ключи не нужны.
- Интернет может понадобиться **один раз** для сборки образов и скачивания весов моделей. После загрузки моделей обработка должна работать без интернета. Не скачивай модели при каждой обработке.
- Не обещай высокую скорость без замеров. При отсутствии GPU сервис должен иметь возможность работать на CPU.

## Минимальная архитектура

1. **Go-приложение** — HTTP API, простая веб-страница, загрузка файлов, список встреч, статусы обработки, просмотр результатов и экспорт.
2. **Python-сервис** — только локальное распознавание аудио через `faster-whisper`; небольшой HTTP-интерфейс с `/health` и `/transcribe`.
3. **Ollama** — локальный запуск `gemma4:12b`; Go отправляет ему текст встречи по внутренней Docker-сети.
4. **SQLite** — хранение встреч, транскриптов и результатов. Аудио и экспорты — в локальной папке/volume.
5. **Docker Compose** — запускает сервисы и сохраняет модели и данные между перезапусками.

Используй стандартный `net/http` в Go, `modernc.org/sqlite`, Python FastAPI и `faster-whisper`. Не добавляй фронтенд-сборщик: достаточно HTML-шаблонов, CSS и небольшого JavaScript.

## Возможности MVP

- Загружать распространённые аудиофайлы: WAV, MP3, M4A, MP4 и WebM; проверять расширение, размер и ошибки обработки.
- Преобразовывать аудио в текст локально, сохранять сегменты с таймкодами.
- Анализировать транскрипт через `gemma4:12b` и получать валидный JSON со следующими полями:
  - краткое содержание;
  - ключевые решения;
  - задачи: текст, ответственный и срок — только если они явно прозвучали;
  - риски и открытые вопросы;
  - подтверждающие цитаты и таймкоды, если доступны.
- Не выдумывать факты, имена, сроки или ответственных. Если данных нет, указывать `null` или пустой список. Считать ответ модели недоверенным: проверять JSON и показывать понятную ошибку, если его нельзя разобрать.
- Показывать статусы: загружено, распознаётся, анализируется, готово, ошибка. Не блокировать HTTP-запрос на всё время обработки.
- Просматривать транскрипт и протокол, скачивать результат в Markdown и JSON. SRT можно добавить после рабочего MVP.
- Обрабатывать длинные записи частями, сохраняя порядок и смещение таймкодов.

## Простота и качество

- Сделай одну понятную структуру проекта без избыточных слоёв и десятков зависимостей.
- Настройки вынеси в `.env.example`: порты, пути хранения, модель Whisper, адрес локального Ollama и имя модели Gemma. **Не добавляй переменные для внешних ключей.**
- Добавь health-check, таймауты, ограничение размера загрузки, безопасную обработку имён файлов и корректное завершение процессов.
- Напиши несколько важных тестов: разбор ответа LLM, обработка ошибок, хранение встречи и проверка таймкодов. Добавь синтетическую текстовую фикстуру, чтобы проверить анализ без запуска Whisper.
- В README на русском опиши архитектуру, требования к памяти, запуск через Docker Compose, однократную загрузку `gemma4:12b` и модели Whisper, проверку работы без интернета, экспорт и известные ограничения.
- Не добавляй доставку в Telegram/Slack, регистрацию, роли, биллинг, векторную БД, диаризацию, облачный режим или сложную аналитику.

## Порядок работы

Работай небольшими этапами, подходящими для локальной модели Gemma 4 12B:

1. Кратко покажи план и дерево файлов.
2. Реализуй минимальный вертикальный сценарий: загрузка аудио → локальный Whisper → локальная Gemma → сохранение результата → просмотр в браузере.
3. Добавь Docker Compose, инструкции загрузки моделей и проверку запуска.
4. Затем добавь тесты, обработку ошибок и экспорт.

На каждом этапе выдавай **полное содержимое только новых или изменённых файлов**, команды запуска и проверки. Не выводи заново неизменённые файлы. Не оставляй фиктивную реализацию, `TODO` или псевдокод вместо рабочего кода. Проверяй согласованность портов, путей, переменных окружения и Docker Compose. Если ответ слишком большой, заверши текущий рабочий этап и укажи следующий этап одной строкой.

**Критерий готовности:** после однократной сборки образов и загрузки моделей пользователь может отключить интернет, выполнить `docker compose up`, загрузить аудиофайл и получить локальный транскрипт и протокол. Ни аудио, ни транскрипт не покидают компьютер.
